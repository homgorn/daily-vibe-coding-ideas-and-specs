## Фаза 1 — Обкатка пайплайна (14 дней) [~] В РАБОТЕ
**Цель:** движок стабильно выдаёт ≥30 фич/день, ≥5 идей/день, ≥3 спеки/неделю; индексы строятся; валидация не пропускает мусор.
**Правила:** каждый день — ручной ревью дайджеста (10 мин); фидбек (рейтинги 1–5) в БД; пустой день — тоже отчёт.
**Осталось:**
- Реальный LLM-провайдер (вместо mock)
- GITHUB_TOKEN + живой fetch
- News-модуль
- 14 дней стабильных прогонов
**Выход из фазы:** 14 дней без падений, KPI-таблица заполнена, первая неделя публикаций в GitHub Pages.

## Модель обновления
- **Weekly (пн):** обновление frameworks (spec-kit, BMAD-METHOD submodules) + диф + constitution; legal-чек-лист; KPI-сводка
- **По событию:** новый ингест/новость → инкрементальный прогон

## SDD-структура (Spec-Driven Development)
- `constitution.md` — нерушимые правила
- `spec.md` — what/why
- `plan.md` — how (технический план)
- `tasks.md` — разбивка на задачи с статусами
- `docs/10-decisions/ADR-{NNN}-{slug}.md` — Architecture Decision Records
- `docs/10-decisions/_TEMPLATE.md` — ADR-шаблон
- Реализовано: ADR-001 (SQLite+MD), ADR-002 (Spec Kit+BMAD), ADR-003 (8-agent validation), ADR-004 (multi-level index), ADR-005 (LLM provider)
