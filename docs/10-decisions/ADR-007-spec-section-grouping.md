# ADR-007: Генерация спеки разбита на группы секций

**Date**: 2026-09-27
**Status**: Accepted
**Deciders**: owner
**Consulted**: замеры на живых free-моделях OpenRouter
**Informed**: —

## Context

`generate_spec()` просил у модели один JSON-объект со всеми 12 секциями спеки
и полагался на `json.loads`. С подключением живого LLM (ADR-006 закрыл silent
fallback) оказалось, что этот путь **не работает вообще**.

Замеры на `nvidia/nemotron-3-ultra-550b-a55b:free`, реальный спека-промпт
(`tools/diagnose_truncation.py`):

| max_tokens | finish_reason | completion tokens | `extract_json_object` |
|---|---|---|---|
| 2000 | length | 2000 | нет |
| 4000 | length | 4000 | нет |
| 6000 | length | 6000 | нет |
| 8000 | length | 8000 | нет |
| 16000 | stop | 9727 | **нет** |

Два вывода, которые нельзя получить рассуждением:

1. **Проблема не только в лимите.** Даже когда модель заканчивает сама
   (`finish_reason=stop`, 9727 токенов), JSON не парсится. Поднять `max_tokens`
   до 16384 недостаточно.
2. **Поднять лимит ещё и дорого.** На free-пуле 16k токенов — минуты ожидания
   в общей очереди. Ранее замер: 4096 → ~7 минут на вызов.

Контрольный эксперимент (`tools/inspect_response.py`): те же 4 секции в одном
запросе → **2331 токен, `finish_reason=stop`, парсится без единой правки**.

То есть размер ответа модели, а не парсер, был узким местом: на 12 секций она
разворачивает >9.7k токенов и не доводит объект до валидного состояния.

Побочный эффект, замеченный при разборе ответа: модель выдумывает данные —
«73% репозиториев заброшены (по опросу OpenSSF 2023)», ссылки на semver.org и
containers.dev, которых не было в source materials. Правила grounding в
промпте не помогали, потому что модель писала 10k токенов за один раз.

## Decision

1. **`SPEC_GROUPS`** — 12 секций разбиты на 3 группы по 4:
   - `Problem and value`: problem, solution, target_user, features
   - `Architecture`: tech_stack, data_model, api, ui_ux
   - `Shipping`: monetization, risks, launch_checklist, cited_sources
2. **Один вызов на группу.** `MAX_SECTIONS_PER_CALL = 4` — константа, а не
   магическое число в промпте; тест падает, если группа разрастётся.
3. **Частичный успех.** Упавшая группа помечает свои секции
   `(not provided by model)` и добавляет `*Partial spec: <причины>*`.
   `FALLBACK_MARKER` ставится **только когда не собрано ни одной секции** —
   иначе 4 выигранные секции были бы выброшены из-за соседней ошибки.
4. **Grounding-правила в каждом промпте:** только source materials, никаких
   выдуманных статистик/дат/цитат/версий/URL, при отсутствии данных писать
   «unknown», `cited_sources` только из переданных URL.
5. `max_tokens` для стадии `expensive` — 2000 на группу вместо 4096 на всё.

## Consequences

### Positive
- Спеки действительно генерируются: 2331 токен на группу — модель заканчивает
  сама, JSON валиден.
- Сбой стоит 4 секции вместо 12, и виден в артефакте.
- Вызовы независимы → готовы к параллелизации.
- Модель получает 2.3k токенов контекста ответа вместо 10k: меньше шанс
  выдумать факты, grounding-правила читаются.

### Negative
- Три вызова вместо одного: больше сетевых запросов, три записи в LLM-кэш.
- Порядок секций в артефакте задаётся `SPEC_SECTIONS`, а не порядком ответа.
- Три независимых ответа могут разойтись по тону; согласованность не
  гарантирована (это кандидат на следующий шаг — общий контекст-резюме).

### Neutral
- `MAX_SECTIONS_PER_CALL` ограничивает только форму запроса, не число вызовов.

## Alternatives Considered

| Alternative | Pros | Cons | Why rejected |
|---|---|---|---|
| Поднять `max_tokens` до 16k | Ноль кода | Минуты в очереди, и всё равно не парсится (9727 tok, `stop`) | Не работает и дорого |
| Строгий JSON через `response_format` | Модель обязана вернуть JSON | Часть провайдеров/моделей игнорирует; поведение на free-пуле не проверено | Не проверено, оставлено на потом |
| Попросить markdown-секции без JSON | Проще | Теряем структуру, парсить придётся эвристиками | Хуже текущего варианта |
| Один вызов, но кратче (по 1–2 секции) | То же, что выбрано | 6–12 вызовов вместо 3 | 4 секции — минимум, при котором вызов ещё не обрезается |

## Compliance

- [x] Data is truth — grounding-правила прямо запрещают выдуманные цифры и URL
- [x] Validation before publication — поведение фолбэка не изменилось (ADR-006)
- [x] Secrets only in .env — не затронуто
- [x] Markdown + index — не затронуто
