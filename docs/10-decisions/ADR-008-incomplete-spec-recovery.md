# ADR-008: Частичная спека перегенерируется, а не остаётся навсегда

**Date**: 2026-09-27
**Status**: Accepted
**Deciders**: owner
**Consulted**: 11 артефактов в `publish/en/specs/`, 4 прогона регенерации
**Informed**: —

## Context

ADR-006 ввёл fail-loud генерацию: неудача видна, а не замаскирована
шаблоном. ADR-007 разбил генерацию на группы. Обе правки дали рабочие спеки —
но выявили третий дефект, который молчал дольше всех.

`run_spec_generation()` отбирал идеи так:

```sql
SELECT i.id FROM ideas i
LEFT JOIN specs s ON i.id = s.idea_id
WHERE i.status IN ('new', 'watching') AND s.id IS NULL
```

Строка спеки появляется, даже если тело частичное: `write_spec()` пишет файл
всегда, а `save_spec()` вызывается независимо от того, заполнились ли все
секции. Дальше идея переводится в `status = 'spec'` и выпадает из отбора.

Итог: **спека с четырьмя пустыми секциями становилась постоянной.** Ни один
последующий прогон её не видел. Обнаружилось это случайно — при сверке
`audit_specs.py` после регенерации обнаружились файлы, содержащие старое
имя группы `Architecture`, которого в коде уже не было:

```
10_f-droid-2-0.md | empty: Tech Stack, Data Model, API, UI/UX
  > *Partial spec: Architecture: unparseable response*
```

Файл был написан прогоном **до** разбивки на 4 группы. То есть он даже не
участвовал в последней регенерации.

Два следствия, которые делали дефект дороже, чем он выглядел:

1. `reset_fallback_specs.py` удалял только файлы с `FALLBACK_MARKER`.
   Частичные не попадали под размах, поэтому и ручной инструмент не помогал.
2. `save_spec()` делал голый `INSERT`. Как только частичные спеки начали бы
   перегенерироваться, каждая попытка добавила бы ещё одну строку — тихая
   дубликация, которую никто не заметил бы, пока не посчитал строки.

## Decision

1. **`spec_is_incomplete(spec_path) -> bool`** в `engine.spec` — единственное
   определение полноты. `True`, если файла нет, либо в нём
   `FALLBACK_MARKER`, либо `INCOMPLETE_MARKER = "(not provided by model)"`.
   Таблица `specs` хранит только путь, поэтому полнота — свойство файла.
2. **`select_ideas_needing_specs(conn)`** выбирает идеи, у которых спеки нет
   **или** чей файл неполон, и включает статус `'spec'` в допустимые.
   Механизм починки теперь в пайплайне, а не в ручном инструменте.
3. **`save_spec()` идемпотентен**: `DELETE` по `idea_id` перед `INSERT`.
   Одна идея — одна строка, независимо от числа попыток.
4. `reset_fallback_specs.py` использует то же `spec_is_incomplete`, плюс
   исторические `LEGACY_FILLERS` (тексты без маркера).

## Consequences

### Positive
- Частичная спека чинится обычным `run` — без ручного вмешательства.
- Пайплайн и тулза не могут разойтись в определении «полноты».
- Регенерация не плодит дубликаты строк.
- `run_spec_generation` на каждом прогоне читает файлы спек — это чекинг
  полноты вместо доверия к факту существования строки.

### Negative
- Идея, у которой модель стабильно не может заполнить `api`/`ui_ux`,
  перегенерируется на каждом прогоне. Расход ограничен
  `models.budget_minutes.spec` (45 мин), так что зависнуть нельзя, но часть
  бюджета уходит впустую.
- Чтение файлов на каждом прогоне: 12 файлов, на практике бесплатно.

### Neutral
- `(not provided by model)` теперь двойная нагрузка: маркер для человека и
  условие для машины. Это осознанно — один токен, одна правда.

## Alternatives Considered

| Alternative | Pros | Cons | Why rejected |
|---|---|---|---|
| Хранить полноту в `specs` (новая колонка) | Не читать файл | Миграция схемы; рассинхрон с файлом всё равно возможен | Файл — источник истины; колонка продублирует его и разойдётся |
| Отдельная команда `repair-specs` | Явное действие | Нужно помнить и звать руками; артефакт остаётся сломанным до этого | Починка должна быть свойством прогона, а не дисциплиной |
| Удалять частичные спеки автоматически | Нет мусора | Теряется уже оплаченный текст 8 секций | Потерянные секции — реальный ущерб, повтор их восстановит дёшево |
| `REPLACE INTO` вместо `DELETE`+`INSERT` | Короче | Нужен `UNIQUE(idea_id)`, без него не сработает | Та же цена, хуже видно намерение |

## Compliance

- [x] Data is truth — неполная спека не публикуется и не маскируется
- [x] Validation before publication — гейт не изменился, но теперь наполнение
      реально восстанавливается
- [x] Secrets only in .env — не затронуто
- [x] Markdown + index — не затронуто
