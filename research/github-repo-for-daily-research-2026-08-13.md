## План проекта

### 1. Репа
`daily-vibe-coding-ideas-and-specs` (нужен `gh auth login` от тебя) — private на старте, позже public как канал публикации. Локальная папка — текущая.

### 2. Структура
```
├── AGENTS.md, README.md, CHANGELOG.md, TODO.md, ROADMAP.md
├── constitution.md / spec.md / plan.md / tasks.md   ← Spec Kit артефакты самого движка
├── src/
│   ├── engine/fetch/      ← GH trending, HN, PH, RSS, npm, топ-репы по категориям
│   ├── engine/store/      ← MD + SQLite
│   ├── engine/synthesize/ ← кластеры → идеи → тренды рынка
│   ├── engine/spec/       ← гибрид Spec Kit + BMAD → spec.md + tasks.md для мультиагентов
│   ├── engine/publish/    ← MD в репу; WP — отдельный модуль позже
│   ├── index/             ← автогенерация многоуровневого индекса + вики
│   └── cli.py
├── tests/                 ← pytest: целостность индекса, схема БД, ≥30 записей/день, битые линки
├── frameworks/            ← spec-kit + bmad-method (git submodules, weekly-апдейт скриптом)
├── research/              ← все дип-рисёрчи в MD (этот попадёт первым)
├── data/YYYY-MM-DD/       ← raw/ + notes/ + specs/

├── wiki/                  ← LLM-вики всех спеков и идей
├── db/                    ← SQLite (схема: sources, items, clusters, ideas, specs, index_links)
├── prompts/               ← шаблоны промптов для мультиагентов
└── config.yaml            ← источники, расписания, категории
```

### 3. Движок (чистый Python, модули)
**Дневной цикл** (OpenChamber schedule, напр. 07:00): fetch ≥30 находок → дедуп/кластеризация → LLM-синтез 3–5 идей + срез рынка → генерация спеков (конституция + BMAD-роли) → запись MD + SQLite → пересборка индекса и wiki → changelog → commit+push.
**Weekly** (пн): обновление submodules spec-kit/BMAD, диф, апдейт constitution, weekly-дайджест.

### 4. Скиллы
**Юзать (существующие):** research-decomposer, multi-source-researcher, fact-checker, knowledge-synthesizer, report-generator, task-atomizer, quality-gate, session-checkpoint, content-decomposer, seo-optimizer (для WP), database-designer, test-designer, github-manager.
**Создать (новые, после запуска движка):**
1. `daily-research-engine` — пайплайн fetch→store→index
2. `sdd-spec-builder` — гибрид Spec Kit + BMAD под мультиагентов
3. `trend-synthesizer` — сырые находки → кластеры → идеи
4. `multi-level-indexer` — автогенерация индексов MD + вики
5. `framework-updater` — weekly апдейт spec-kit/BMAD

### 5. Что ты упустил (дополнения)
- **Вендоринг фреймворков** (submodules) — иначе «обновлять раз в неделю» не на чем
- **Quality gate перед публикацией**: автотесты обязательны до push
- **Юридическое для WP**: права на цитаты/скриншоты, trademark BMAD в текстах, E-E-A-T
- **Метрика успеха** (например: ≥30 фич/день, ≥5 спеков/нед, uptime схедьюла)
- **Backup-стратегия** (репа = бэкап; SQLite можно коммитить — он маленький)
- **Seeding**: первые 14 дней «прогревочных» датасетов до публикации
- **Аналитика**: в модуле WP — Google Search Console, какие идеи заходят

## 🧠 3. БД и перелинковка (ответ на «не знаю как лучше»)

**SQLite** — рекомендую: файловая, коммитится в git, хватает на десятки тысяч спеков, SQL-граф для перелинковки. DuckDB избыточен; Postgres добавим только если WP начнёт тянуть напрямую (сначала — экспорт JSON через REST, модульно).

Схема: `sources, items, clusters, ideas, specs, tags, item_tags, related_links, channels, launches`. **related_links** = граф «похожие» (идея↔идея через общие теги/кластеры, идея↔репо, спека↔спека) — автогенерация секции «Similar» в каждом MD-артефакте, единый источник для GitHub/WP/соцсетей. Фронтматтер каждого файла содержит `tags: []` и `related: []`.

## 🚀 4. Кнопка «открыть в IDE» (рисёрч сделан)

Все агенты имеют headless-режим, поэтому для каждой спеки движок генерирует **`launch.md`** с готовыми командами + JS-кнопки copy-to-clipboard для WP:

| IDE | Команда |
|---|---|
| Claude Code | `claude -p "$(cat spec.md)"` |
| OpenCode | `opencode run "$(cat spec.md)"` |
| Codex CLI | `codex exec "$(cat spec.md)"` |
| Cursor | `cursor agent -p "$(cat spec.md)"` |
| Antigravity | `antigravity run "$(cat spec.md)"` |

Кнопка «Copy» → буфер; кнопка «Run» → терминал. Референс-паттерн: Markagent (export templates под каждый агент). Дополнительно: каждая спека = чистый markdown, пригодный для любой текстовой IDE.

Твои сценарии, один вход:

- **Файл-режим**: скинул PDF/ссылку/текст в `ingest/` → то же самое.
- **Скриншот-режим**: картинка → OCR → анализ (в дашборде кнопка).
