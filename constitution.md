# Constitution — нерушимые принципы проекта

Источник: Spec Kit (spec-driven development). Эти правила не обсуждаются — любые изменения через ADR и явное согласие владельца.

## 1. Данные — правда
- Никогда не выдумываем данные: звёзды, даты, цитаты, цифры — только из фетчей. Каждое утверждение в артефактах имеет `Cited:` блок с источником (URL, title, дата обращения).
- Ссылки только на whitelist-домены (Wikipedia, arXiv, MDN, W3C, официальные доки, GitHub, .gov/.edu, IEEE/ACM); чёрный список — спам/агрегаторы.
- Битые внешние ссылки = FAIL валидации, публикация невозможна.

## 2. Авторские права
- Контент проекта: CC BY-NC-ND 4.0. Код: AGPL-3.0.
- Чужой контент не копируем дословно — пересказываем своими словами + ссылка на оригинал.
- Trade-mark'и (BMAD™ и др.) не используем в коммерческих текстах проекта как свои.

## 3. Качество перед публикацией
- Публикуется только то, что прошло все 5 валидационных агентов (data/text/image/video/post) + SEO/GEO-чекер + legal-check.
- Каждый артефакт: frontmatter (tags, related, origin, viability_score), индекс в MD и БД, запись в чейнджлоге.
- Формат: всё в Markdown, всё индексируется (глобальный → день → категория → кластер → тег → идея).

## 4. Технологическая дисциплина
- Чистый, модульный, тестируемый код. Комментарии в коде — только по явной просьбе.
- Секреты — только в .env (в git — .env.example). В git не попадает ничего из .env.
- Каждая фаза пайплайна переживает падения без потери данных (частичное сохранение, run-лог, ретраи).
- LLM-кэш обязателен; бюджет токенов контролируется; дешёвая модель — на массовые операции.

## 5. Легальность 100%
- Все публикации соответствуют правилам площадок (GDPR, EU AI Act маркировка, FTC disclosure, YouTube synthetic media, Meta Ads политики, CAN-SPAM).
- Legal-чек-лист обновляется еженедельно; без его прохождения — никаких публикаций.
- Дисклеймеры (инвест-материалы, обзоры) — обязательны.

## 6. Процесс и прозрачность
- Каждый прогон: run-лог с таймингами и статусами. Каждая сессия чата: резюме в logs/chat/.
- Решения — через ADR в docs/10-decisions/.
- Владелец всегда в курсе: утренний статус (owner-бот/TG), weekly-отчёт (KPI).
- Пайплайн должен быть максимально автоматическим, но с ручными шлюзами на одобрение перед публикацией в чужие каналы.
